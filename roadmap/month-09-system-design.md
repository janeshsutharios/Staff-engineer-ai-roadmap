# Month 09 — System Design & Distributed Systems

**Status:** Not started

## Outcome

Use evidence to justify architectural choices.

## Starting point

Complete month 8: a deployed system with measurements and a runbook.

## Weekly sequence

| Week | Work in this order |
|---|---|
| 1 | State users, requirements, capacity assumptions and service objectives. Load-test one realistic workflow. |
| 2 | Study queues, caching, load balancing and horizontal scaling using the bottleneck you measured. |
| 3 | Learn consistency, replication and failure handling; discuss sharding and distributed transactions conceptually before deciding whether you need them. |
| 4 | Write a short design proposal comparing options, request review and measure one improvement. Include AI quality and cost alongside throughput. |

## Ready to move on when

Defend a scaling decision with before/after evidence and describe its failure behavior. If this is not yet comfortable, extend this month before continuing.

## Optional / defer

Implementing sharding, distributed transactions or microservices without a demonstrated need.

## Topic reference

- Load balancing, caching, queues and event-driven architecture.
- Replication, consistency, sharding and distributed transactions.
- Horizontal scaling, observability, rate limiting and fault tolerance.

## Build

Load-test an existing project and improve its measured bottleneck; write designs for document processing and notification infrastructure.

## Completion checklist

- [ ] State requirements, capacity assumptions and service objectives.
- [ ] Compare alternatives before adding infrastructure.
- [ ] Capture before/after results and explain remaining limits.

## Career & income objective

Turn project evidence into Staff-level portfolio case studies.

## Portfolio & Staff-level evidence

Write an RFC, request peer feedback and record the resulting decision.
